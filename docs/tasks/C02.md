# C02 AI 对话页

> 执行：Cursor。分支：`c02-ai-chat`（从 main 拉，和 C01 互不依赖）。开始前读 `docs/cursor/PLAN.md`、`docs/UI.md`、`.cursor/rules/`。

## 背景

本机服务已有 `POST /api/chat`：把消息转发给本机 Hermes（127.0.0.1:8642），把 Hermes 的 SSE 原样流回来；`api.ts` 里的 `api.chat()` 已经能解析出 `delta`（文字）、`tool`（工具开始/完成）、`error`、`done` 四种事件。
Hermes 通过 MCP 调用我们的财务工具（`mcp_server.py`），工具在 Hermes 里的名字可能带前缀（例如 `mcp_finance_search_vouchers`），按后缀匹配。
用户要的样子：像 Claude 的聊天界面；所有问答都在这一页，不另做知识库问答页；回答里提到的凭证号是可点的标签，点开在右侧栏看凭证。原型：`docs/prototype/Chat.dc.html`。

## 任务

### 后端（services/core）

1. **对话存储**：新表 `chat_sessions(id TEXT 主键, title, created_at, updated_at)`、`chat_messages(id, session_id, role, content, tools_json, created_at)`，走 `db.py` 迁移（`SCHEMA_VERSION` 升到 2）。
2. **接口**：
   - `GET /api/chats` 会话列表（按 `updated_at` 倒序）；`GET /api/chats/{id}` 会话和全部消息；`PATCH /api/chats/{id}` 改标题；`DELETE /api/chats/{id}`。
   - `POST /api/chat` 改为：请求体 `{session_id?: string, message: string}`。没有 `session_id` 就新建会话（标题取用户第一句话的前 20 个字）。服务端从库里取历史消息拼成 `messages` 发给 Hermes，并带 `X-Hermes-Session-Id: <session_id>`。先存用户消息；流结束后把累积的回答文字和用到的工具列表存为助手消息。流的第一个事件是 `event: session` + `{"session_id": "..."}`，让前端知道新会话的 id。
   - 用户中途停止（客户端断开）时，已收到的部分也要存下来，并在内容末尾标记“（已停止）”。
   - `GET /api/hermes/status`：用 `HERMES_API_KEY` 请求 Hermes 的 `GET /v1/models`，返回 `{"configured": bool, "reachable": bool, "model": string|null}`，超时 2 秒。
   - `GET /api/vouchers/lookup?no=记-0003&period=2026-11`：按凭证号找凭证；不给 `period` 时返回所有期间里匹配的凭证（列表）。
3. **假 Hermes**（开发和测试用）：`services/core/src/finance_core/dev/fake_hermes.py`，`python -m finance_core.dev.fake_hermes` 在 8642 端口起一个 OpenAI 兼容的假服务：校验 Bearer key，流式返回几段文字、一个 `hermes.tool.progress` 的 running/completed 事件对，回答里包含“记-0003”。没装 Hermes 的电脑也能开发和测试这个页面。
4. 测试：会话增删改查、`/api/chat` 用假 Hermes 跑通（存了两条消息、第一个事件是 session）、Hermes 不可达时返回 `hermes_unreachable` 错误事件、`status`、`lookup`。

### 前端（apps/desktop）

5. **页面** `pages/ChatPage.tsx`，路由 `/chat`（以及 `/chat/:id`）：
   - 主区：消息流，宽度最多 760 居中。用户消息靠右浅灰气泡；助手消息不加气泡，直接排版（像 Claude）。
   - 助手消息用 Markdown 渲染（`react-markdown` + `remark-gfm`，都是 MIT），表格用 `.tbl` 样式、数字列右对齐。
   - 工具进度：回答上方显示一行小标签，例如“查询凭证…”变成“已查询凭证”，带对勾。工具中文名表：`search_vouchers` 查询凭证、`get_voucher` 查看凭证、`list_accounts` 查看科目、`account_balance` 查询余额、`trial_balance` 生成余额表、`create_draft_voucher` 生成草稿凭证；没列到的显示原名。
   - **凭证号标签**：回答里匹配 `记-\d{4}` 的文字渲染成 `.chip` 标签（带账本图标）。点开后右侧栏显示凭证详情：复用 `VoucherDetail`；查到多张时先列出让用户选。AI 刚生成的草稿凭证，标签旁加 `.tag.ai`“AI 草稿”。
   - 每条助手消息悬停时显示“复制”“重新生成”（只有最后一条有重新生成）。
   - 底部输入框：多行自动增高（最多 8 行），Enter 发送、Shift+Enter 换行；生成中按钮变成“停止”（AbortController）。
   - 空状态：衬线标题“问问你的账本”，下面三个建议问题标签（“11 月银行存款还剩多少？”“查一下本月差旅费凭证”“帮我做一张支付办公用品 500 元的凭证”），点击直接发送。
   - 顶部 Hermes 状态：用 `<TopActions>` 放一个状态点（`/api/hermes/status`：绿=在线、灰=未配置、红=连不上），悬浮提示写清楚怎么办（未配置→“按 docs/tasks/T02.md 配置 Hermes”）。连不上时输入框可用，但发送后显示错误提示条。
6. **会话列表**：放在左侧导航“AI 对话”下面的“最近对话”分组（原型里有），显示最近 6 个，点击打开；对话页顶栏加“新对话”按钮。会话的重命名、删除放在对话页标题旁的 `…` 菜单里（删除用页面内确认）。
7. `api.ts`：新增 `chats`、`chat`（改为新请求体，并多一种 `session` 事件）、`renameChat`、`deleteChat`、`hermesStatus`、`lookupVoucher`，同步改 `docs/CONTRACT.md`。

## 验收标准

1. `pytest` 全部通过；`npm run build` 通过。
2. 起假 Hermes（`python -m finance_core.dev.fake_hermes`，环境变量 `HERMES_API_KEY` 两边一致）：发一句话，回答逐字出现，工具标签从“查询凭证…”变成“已查询凭证”，回答里的“记-0003”是标签，点开右侧栏显示这张凭证。
3. 重启本机服务和桌面端后，左侧“最近对话”里还在，点开历史消息完整。
4. 生成中点“停止”，回答停住并显示“（已停止）”，再发下一句正常。
5. 关掉假 Hermes 后发送：显示“连不上 Hermes，请确认它已启动”，状态点变红。
6. 不设 `HERMES_API_KEY` 时状态点为灰，悬浮提示指向 T02。
7. 在用户电脑上接真 Hermes（T02 完成后）：问“11 月管理费用一共多少”，能回答 4840.00 并引用凭证号（这一条由 Claude 和用户在 T02 后一起验收，Cursor 报告里写“未验证”即可）。
8. 深色模式正常；报告附浅色、深色、出错三张截图。

- 语音输入、上传附件给 AI。
- 飞书/企业微信接入。
